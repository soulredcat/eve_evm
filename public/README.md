# Public runtime

Planning only; the runtime is not implemented yet.

Role ownership and standalone distribution are absolute requirements. Public-specific entry points and orchestration stay here. `components/recovery-store/` owns bounded durable records; `components/node-policy/` owns validated resource/watermark/readiness/source policy; `components/interop/` owns typed public chain/asset/route metadata. The completed copy-ready public directory must include every required dependency, lockfile/toolchain, sanitized configuration and notices, and pass build/run after copying only this directory to an unrelated location. No private master implementation or unresolved parent-directory path is permitted. These component foundations are not yet a complete public node or passing standalone distribution.

Permissionless RPC/P2P node with bounded transaction ingestion, verified state queries, snapshot/delta bootstrap, peer data distribution and explicit readiness. It has no voting power unless a separately registered validator runtime is co-located.

A public package must build without master implementation or secrets. Default `PUBLIC` keeps hot execution/query state in RAM while storing finalized blocks and recoverable checkpoints on local durable storage. RAM-only operation is an explicit development/ephemeral alternative, not the default. State sources may be peers or master, but source identity is not a trust anchor.

An isolated asynchronous storage worker consumes ordered immutable finalized batches, with one durable commit owner per local namespace. Reserve bounded handoff capacity before RAM application. Execution/query state locks are not held across disk writes or fsync. Bound queued bytes, batch count and oldest-item age; budget worker CPU, database/page cache, retained buffers, snapshots and compaction. B0 must freeze versioned measured limits and saturation/recovery scenarios. Shared-resource overhead remains measurable; no zero-interference guarantee is made.

Serve locally verified RAM-applied state only within the declared readiness/lag policy and report finalized, applied, durable and authenticated state heights separately, preserving plan 12's H/H+1 binding. Enqueue completion or OS page cache does not establish durability: atomically publish durable markers only after required sync succeeds and complete recovery coverage exists. Apply backpressure and remove readiness or stop local ingestion before declared limits are exceeded.

A public recovery-store profile may persist finalized block payloads, authentication, protocol/configuration, security-profile and validator-set history, and periodic consistent checkpoints instead of the full hot state each height. Its durable recovery watermark requires a complete verified checkpoint-to-height replay sequence; report checkpoint and full state-store durable heights separately when applicable. Restart replays local durable blocks and checks exact commitments/receipts before fetching missing tail data. Full `StateStore` atomic commits are unchanged.

After a crash, reconstruct working state from the last complete authenticated local durable checkpoint/history, recover any lost queued tail from authenticated durable peers, and restore readiness after verification. An ephemeral replica fully reboots through verified peer data. Never prune the sole recoverable finalized copy. Validator anti-double-sign state must remain durable before releasing a signature, even when a validator shares this machine; public asynchronous storage grants no exception.

Master NVMe followers stay outside the mandatory transaction path. Read [plan 32](../docs/plan/32-regional-masters-and-public-persistence.md), plans [02](../docs/plan/02-state-and-storage.md), [14](../docs/plan/14-block-and-state-commitment-spec.md), [16](../docs/plan/16-genesis-upgrade-and-recovery.md), and 10, 15, 18–20 and 22. Public requests and persistence must not starve validator consensus when roles share a machine. These are implementation requirements, not evidence of a running worker or verified performance.
