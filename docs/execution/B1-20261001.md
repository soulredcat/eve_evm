## Implementation and role ownership

Validator state owns one canonical account/storage/system trie implementation,
ordered journals, complete views, genesis, canonical whole commits and both state
domains' commitments. The original EVM root API delegates to it. Strict recovery
bytes validate Shanghai transaction/receipt encodings, cumulative gas/bloom,
code content and roots. A separate local content digest binds code/history beyond
consensus roots; historical BLOCKHASH data is checked against retained headers.

Public recovery storage owns one private RocksDB object, an exclusive writer,
read-only snapshots and cache-first complete views. One WAL-enabled synced batch
contains state/system/code/history/header/transactions/receipts/roots/identities
and durable marker. Exact replay cannot repeat effects; ambiguous write/sync or
post-sync publication errors fence advancement pending reopen/reconciliation.
Cache/query guards do not span I/O. Sequence snapshots match acknowledged durable
publication and keep old reads stable during later commits.

Checksummed snapshots stage complete bounded recovery frames and publish a ready
manifest only after sync. Activation requires a new namespace; incomplete/budget-
limited staging remains inactive without changing live/source data. No snapshot
checksum or root match is upgraded into authenticated source finality.

Master owns the explicit DEV_ALL_IN_ONE CLI composition: real genesis, init,
reopen, EVM apply, snapshot and restore. It rejects production/master-sync-only/
unacknowledged authority, unsupported profiles, private-signing JSON fields and
nonignored/escaping data paths. Status reports authenticated validator finality
false. Genesis bonds debit funded owners and credit f100 once, preserving supply.

The complete-state executor retains the serial oracle, reserves both materialized
and candidate clones, preserves untouched slots, and updates the existing fee
allocation/system ledger once. It never hashes a partial lazy cache as complete
state or hides persistence failures inside REVM DatabaseCommit.
