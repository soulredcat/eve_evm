# B0 fresh-checkout CI repair — 2026-10-01

The [first hosted foundation run](https://github.com/soulredcat/eve_evm/actions/runs/36767059472)
for main commit b799d1c failed during tool provisioning, before the complete gate.
The local 205-case B0 acceptance remains the recorded local result; that hosted
attempt is FAIL, and its skipped gate is not a pass.

The cause was reproduced with the exact pinned Go archive. Under locale C, GNU
tar renders the valid upstream filenames containing Þ as octal escape sequences;
the archive validator correctly rejects backslashes. The local C.UTF-8 host
emitted the real UTF-8 names, so the earlier local provisioning did not expose it.

Archive inspection now explicitly uses C.UTF-8 and escape quoting. Valid UTF-8
names remain intact; controls, backslashes, traversal, foreign roots, escaping
links and special devices retain rejection. A real GNU tar regression constructs
Unicode and tab-bearing filenames and exercises the actual listing helper.

A new managed checkout also exposed a separate strict digest failure: Git's
declared LF policy normalized the reviewed vendor checksum-manifest CRLF bytes.
The generated-binding review now pins the exact committed LF SHA256
5a20e5f3aa8e570e2e6c58dec87765c33b2755c22289a492c25a37c891f98262.
Vendor inputs, source checksums, generator and inclusion-facade bytes are unchanged.
The review still hashes exact bytes; no exclusion or hash check is disabled.

  16 verification cases; none failed or ignored.
- Strict xtask Clippy with all targets and workspace formatting.
- Fresh managed-checkout native structure scan: 571 first-party files,
  15 exact exclusions, zero warnings and zero violations.
- Index whitespace and prohibited-file review before the repair commit.

The whole B0 catalog now includes the additional regression (206 cases total).
Its next hosted run must report its own actual outcome; this scoped test run is
not renamed into a hosted or whole-foundation result.
