# 20 — Tests, acceptance and evidence

## T01 — Evidence is the definition of completion

A checkbox is not evidence. For every completed requirement record implementation paths, test IDs, exact commands, exit codes, tested commit and configuration digests, environment, expected assertion and artifact references. Do not report tests from a different revision as proof of the current diff. A skipped, timed-out, mocked or unavailable gate is not PASS.

The suite includes unit tests, property tests, deterministic replay, serial/parallel differential tests, integration, multi-process devnet, fault injection, fuzzing, packaging and sustained benchmarks. No single coverage percentage proves consensus or economic safety.

## T02 — Required fixture families

Pin a primary Ethereum execution test corpus plus independently sourced encoding/root vectors; record source revision and fixture hashes. Compare supported Shanghai behavior to those vectors and the serial reference, not only to expected values generated by the new parallel implementation itself. Unsupported upstream fork fixtures must be reported separately rather than counted as passed.

Repository fixtures must cover empty/genesis state, every accepted transaction envelope, malformed encoding/signatures, nonce/balance/gas boundaries, CREATE/CREATE2, nested calls/delegatecall, logs, storage refunds, revert/out-of-gas, selfdestruct under the selected fork, system calls, fee rounding, proofs and all consensus metadata domains.

Use deterministic seeds for property tests and save any minimized counterexample. Fixing a bug adds its counterexample permanently. No fixed fake signature/root is accepted by production verification just because tests need a fixture.

## T04 — Commands the implementation must provide

These are **target command contracts, not commands already implemented in this documentation commit**. B0 creates `xtask`, then each bulk extends it:

```sh
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
cargo build --workspace --release --locked
cargo run --locked -p xtask -- verify --bulk B3
cargo run --locked -p xtask -- verify --all
cargo run --locked -p xtask -- devnet up --profile local-4
cargo run --locked -p xtask -- devnet smoke
cargo run --locked -p xtask -- devnet down
cargo run --locked -p xtask -- fault-test --suite recovery
cargo run --locked -p xtask -- package --role public
cargo run --locked -p xtask -- package --role validator
cargo run --locked -p xtask -- bench --profile mixed --duration-secs 3600
```

`xtask` must track its own run directories/process IDs and never kill unrelated services. Missing binaries, tools, selected tests or permissions produce a nonzero failure with a clear category. `verify --all` enumerates mandatory software gates and separately reports unavailable scale/mainnet gates; it may not silently skip them to claim the whole goal complete.

External consensus binaries/containers and test tools are pinned by B0. If a proposed command changes, update the specification, runner, docs and CI together; do not leave an obsolete command as alleged evidence.

## T05 — Development network acceptance

Run four distinct validator processes with independent keys, two public RPC nodes and at least one master follower. Multi-process on one host is acceptable for functional testing, but not evidence of geographic decentralization or WAN capacity.

Test real signed transactions through public RPC. Verify exact hashes, roots, fees, balances and receipts on every role. Kill one validator, then two; partition 2+2; inject delayed/duplicated/corrupt messages; stop master for a retained-data window; rebuild public state; restart validators around sign/commit boundaries; and replay final history from a clean database.

Extend recovery fixtures with T-N09–T-N12: slow/full public storage and checkpoints under concurrent RAM reads; all masters offline while public durable progress continues; public loss with queued unsynced blocks and recovery from authenticated durable peers; stale/invalid fast endpoints and fallback; and two independent masters recovering the same finalized history after partition. Model unsynced write loss explicitly rather than calling process termination a real hardware power-loss test. Include missing/corrupt last-copy cases whose correct outcome is NOT_READY, not fabricated recovery.

Fix readiness/durable-lag thresholds and resource budgets before execution. Assert byte/item queue caps, worker/checkpoint memory, durable-marker ordering, bounded service interference, complete-height activation and duplicate-free replay against the serial oracle. Record finalized/applied/durable/authenticated-state/checkpoint watermarks with correct H/H+1 binding and prove no global RAM lock spans fsync or compaction. A gateway can conceal internal routing without granting source authority; measure private-topology exposure separately from proof correctness.

Simulate network conditions with task-owned proxies or authorized network namespaces. Do not change host networking or require privileged commands silently. If the environment cannot support a test, preserve an executable repro and mark the gate blocked.

## T06 — Evidence artifacts

Each run produces `artifacts/<run-id>/manifest.json` with schema version, timestamp, source commit, dirty-diff digest if applicable, configuration/genesis hashes, dependency pins, host resources, topology, workload/seed, command, exit code, test counts and result summary. Record persistence/readiness budgets, watermarks, endpoint ranking inputs, fault schedule, actual retained recovery sources and simulated-versus-real power-loss scope where applicable. Save sanitized stdout/stderr, machine-readable metrics, fixture references and checksums of large outputs. No keys or tokens appear in evidence.

Commit compact summaries and artifact manifests/references where appropriate; do not put multi-gigabyte traces or live databases into Git. If artifacts are local-only, say so and include exact paths/reproduction commands. Unavailable URLs or fabricated CI run IDs are forbidden.

Root `local-tests/`, `artifacts/`, and `coverage/` are ignored local storage and must never be committed or pushed. Keep reviewed summaries, compact manifests, checksums, and reproduction references in tracked `docs/execution/` files. Required reproducible test source and sanitized fixtures remain versioned in the shared test areas. Follow `CONTRIBUTING.md`; write maintained evidence and test documentation in English.

`docs/execution/EVIDENCE.md` indexes real runs. `STATUS.md` links passing evidence. `HANDOFF.md` records the exact next uncompleted action. Initially all runtime tests are NOT_RUN.

## T07 — Long-running target checks

Before a 1M-TPS claim, run declared W0–W6 profiles separately, a minimum 60-minute measured sustained target run after warm-up, and a 24-hour soak for the strongest sustained claim. Include deterministic post-run state verification, recovery, availability and bounded queue/lag checks. Measure valid unique user transactions, not retries, votes, receipts or replicated copies.

A high ingress rate with growing execution/persistence queues fails. A lower achieved rate is TARGET_UNMET with a bottleneck report. Missing hardware is BLOCKED_INFRA with a runnable deployment package. Neither outcome permits lowering the required workload or deleting an assertion after seeing results.

## T08 — Exit review

Before marking a bulk DONE, the reviewer inspects the full integrated diff, actual test assertions, failure logs, unsafe code, authentication bypasses, unbounded resource use, dead code/stubs and documentation drift. Re-run relevant gates after integration, not only on individual agent branches. Verify a clean checkout can follow the documented workflow.
